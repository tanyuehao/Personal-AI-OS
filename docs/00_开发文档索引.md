## 1. 本文档包的用途

本目录用于替代早期 Word 版本，作为后续 GitHub `docs/`、DeepSeek 辅助开发、代码评审和版本迭代的统一研发基线。

这些文档不再以“项目介绍”为主，而以**实际实现约束**为主：模块怎么拆、数据怎么走、接口怎么定、哪些能力属于 V0.1、哪些必须延后。

## 3. 当前版本边界

### V0.1 必须完成

- 本地/单机部署
- 用户空间
- 文件导入
- 文档解析与切片
- Embedding 与检索
- DeepSeek RAG 问答
- 引用来源
- 基础 Memory：Fact / Experience / Opinion / Decision / Preference
- 对话历史
- 基础日志与测试

### V0.1 明确不做

- 自动执行高风险外部动作
- 复杂多 Agent 自治
- 全量知识图谱
- 人格微调训练
- 自动修改用户价值观/观点
- SaaS 多租户商业平台

## 4. 架构核心

```text
Frontend
   |
Backend API
   |
   +-- Knowledge Engine
   +-- Memory Engine
   +-- Cognitive Engine (V0.1 lightweight)
   +-- Model Gateway -> DeepSeek
   |
PostgreSQL + pgvector + Redis + File Storage
```

## 5. 文档维护规则

- 代码行为与文档冲突时：先确认是否为代码偏离设计，再更新其中一方。
- API、数据库字段、环境变量发生变化时，必须同步更新文档。
- 每个 Release 前进行一次 docs review。
- DeepSeek 生成代码时，优先把相关文档作为上下文，而不是仅靠单条 Prompt。
